# Key message
Six pitfalls and how to head them off

## Talking points
- Every one of these is preventable, and most cheaply by IT
- The first two are about people, the middle two about money and security, the last two about architecture
- The next slides go deeper on cost, keys and service choice

## Slot: table
| Pitfall | What it looks like | What research IT can do |
|---|---|---|
| Credits never used | Award granted, nothing launched | Book an onboarding call in week one |
| Learning curve underestimated | Months before a first result | Offer a starter template and office hours |
| Zombie instances | Bills grow after the work ends | Require tags, alerts and autostop |
| Leaked access keys | Unknown instances appear overnight | Use SSO and short-lived credentials |
| Wrong service | A big VM doing a managed service's job | Review the design before launch |
| Wrong storage | Hot storage for archives; heavy egress | Set lifecycle rules; compute in-region |
